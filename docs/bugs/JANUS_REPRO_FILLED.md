# Reproduction: a mutually recursive stratum that runs for minutes on 10,000 cells

For the janus-datalog side. Written 2026-10-28 against janus-datalog v0.16.0.

## What it is

disasm's filled-before-use proof (EFFECT_CORRECTNESS.md, 8.1) is a set of recursive rules
over the facts of Starflight's kernel. One query over them finishes in 122 ms. Another
needs 5 to 9 minutes on the kernel's 9,931 body cells with one relied-on vector. On all 53
linked segments it grew past 11.7 GB in 20 minutes and was stopped.

The relations are small and the rules are positive Datalog, with `not-join` on stored
attributes only. Nothing here should take more than a second or two.

## The files (`disasm/testdata/janus-repro/`)

| file | what |
|---|---|
| `kernel-facts.jdzl` | the kernel's facts, `ExportBinary` (4.8 MB) |
| `kernel-facts.jdzl.schema.edn` | the schema, in the EDN `schema.ParseSchema` reads |
| `kernel-facts.jdzl.queries.edn` | the rule set and the three queries, as the code has them |

They are regenerated by
`./disasm -file ../game_files/STARFLT.COM -export-facts testdata/janus-repro/kernel-facts.jdzl`.
`TestJanusReproLoads` checks that they load the way the steps below load them.

## Loading it

```go
s, _ := schema.ParseSchemaFile("kernel-facts.jdzl.schema.edn")
store, _ := db.OpenMemory(db.WithSchema(s), db.WithRefuseUnknownAttributes())
f, _ := os.Open("kernel-facts.jdzl")
store.ImportBinary(f)
res, _ := store.Analyze(query, rules) // rules: the rule set text, the queries' % input
```

## What each query does

Measured with `-prove-analyze`, which runs each query under `Analyze` and tallies every
event by name. The engine's total time and the wall time agreed within microseconds.

| query | answer | time | rule iterations | hash joins |
|---|---|---|---|---|
| `[?r :relies/cell ?c] (reach ?c)` | 0 tuples | 122 ms | 89 | 701 |
| `[?r :relies/cell ?c] [?r :relies/mem ?m] (unfilled ?m ?c)`, rules as first written | 0 tuples | 5 min 40 s | 578 | 42,683 (5 min 38 s) |
| the same, `open`/`plain`/`inner` split out of `through` (the rules in the file) | 0 tuples | 9 min 5 s | not recorded | 100,972 (9 min 2 s) |
| `(count ?c)` over `(reach ?c)` | 561 | 418 ms | 99 | 291 |

**First version, top events:**
- `rules/stratum.complete`: 3 events, 17 min (strata overlapping);
- `phase/complete`: 22,537;
- `collapse/success` and `join/hash`: 42,683 each, 5 min 38 s;
- `storage/scan-complete`: 14,179, 36.7 s;
- `cache/rebuild`: 387,228.

**Second version:**
- `phase/complete`: 58,413;
- `join/hash`: 100,972, 9 min 2 s;
- `storage/scan-complete`: 24,201, 51 s.

**The shape of the cost:** about 5 ms per hash join, nearly constant, multiplied by the
number of joins. Splitting the non-recursive parts out of the recursive predicate, which
semi-naive evaluation should only have to join against its deltas, more than doubled the
number of joins.

## The rules

```clojure
[(calls ?c ?k)   [?c :cell/callee ?k]]
[(calls ?c ?k)   [?d :dispatch/cell ?c] [?d :dispatch/candidate ?k]]
[(reach ?c)      [?s :seg/entry ?w] [?w :word/entry ?c]]
[(reach ?n)      (reach ?c) [?c :cell/next ?n]]
[(reach ?e)      (reach ?c) (calls ?c ?k) [?k :word/entry ?e]]
[(vector ?m)     [?r :relies/mem ?m]]
[(open ?c ?m)    (vector ?m) [?c :cell/kind ?kind]
                 (not-join [?c ?m] [?s :store-site/cell ?c] [?s :store-site/mem ?m])]
[(plain ?c)      [?c :cell/kind ?kind] (not-join [?c] [?c :cell/callee ?k] [?k :word/entry ?e])]
[(inner ?c ?k)   [?c :cell/callee ?k] [?k :word/entry ?e]]
[(through ?c ?m) (open ?c ?m) (plain ?c)]
[(through ?c ?m) (open ?c ?m) (inner ?c ?k) (passes ?k ?m)]
[(clear ?m ?k ?e)   (vector ?m) [?k :word/entry ?e]]
[(clear ?m ?k ?n)   (clear ?m ?k ?c) [?c :cell/next ?n] (through ?c ?m)]
[(passes ?k ?m)     (clear ?m ?k ?x) [?x :cell/ends true]]
[(unfilled ?m ?c)   (vector ?m) [?s :seg/entry ?w] [?w :word/entry ?c]]
[(unfilled ?m ?n)   (unfilled ?m ?c) [?c :cell/next ?n] (through ?c ?m)]
[(unfilled ?m ?e)   (unfilled ?m ?c) (calls ?c ?k) [?k :word/entry ?e]]
```

`clear`, `passes`, `through` and `unfilled` are one mutually recursive stratum.
- `clear` is seeded from every colon word's entry, about 2,000 words, for the one vector.
- The longest body is a few hundred cells, which matches the hundreds of iterations.
- The relation's size is bounded by cells × vectors: about 10,000 tuples.

## The sizes

- **Body cells:** 9,931.
- **Words:** 2,064, about 1,000 of them colon words.
- **Vectors relied on:** one (0x5532), relied on by 5 jumps.
- **Cells reached from the entry:** 561.

## What would show the fix

The `unfilled` query answering in the same order of time as `reach` over the same cells,
under a second or two, with the same answer: 0 tuples on the kernel.

`TestFilledRules` in disasm pins down the rules' meaning on a three-word program: proven,
assumed, unreached.
