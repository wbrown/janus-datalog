Total-process CPU for the scan-set-semantics + subquery-projection working
tree vs its baseline commit (27abf3d), measured with fixed work so user+sys
totals are comparable: compiled storage test binaries per side (baseline
built from a worktree at 27abf3d), each run as

  /usr/bin/time -l <binary> -test.run '^$' \
    -test.bench 'BenchmarkComplexQueryCheckpoint$' \
    -test.benchtime 200x -test.count 5 -test.benchmem

= 1000 checkpoint queries + 5 setups per process, runs alternating
baseline/after. The first baseline run was discarded: it built the
worktree's testdata database (one-time setup) inside the measured process.
Machine: Apple M5, go1.26.3 darwin/arm64, 2026-07-22.

Summary (clean runs):

  user+sys CPU              23.46 / 23.20 s     22.61 / 22.55 / 22.50 s   -3.3%

  cycles elapsed            97.94 / 96.58 G     94.57 / 94.20 / 94.43 G   -3.0%
  max RSS                   ~752 MB             ~751 MB             wash
  fixed-work ns/op (mean)   ~18.13 ms           ~17.55 ms           -3.2%

The spreads are non-overlapping on every CPU axis. The calibrated benchstat
(scan_set_semantics_benchstat_2026-07-22.txt) reports wall as a wash at
p=0.165 because variable-iteration calibration buries the ~3% in run-to-run
variance; the fixed-work runs recover it.
